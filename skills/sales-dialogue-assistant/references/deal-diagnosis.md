# 谈单诊断：意图、风险、话术与纠正

本规范为2.1正式规格。方法来自[43卡](method-cards.md)，诊断结构是按用户需求设计；诊断器不是读心术。甲方可能同时包含使用人、采购、付款人和审批人，角色未确认时分别保留，不把接话人自动当最终决策者。

## 输入与证据编号

用户可直接贴聊天、讲述过程、给失败复盘或只问一句怎么回。不强制填写整张表。先保留原话与先后顺序，按U1/U2…建立派生编号，不改用户原稿。标说话人、已知时间、是否节选；截图OCR未核的数字、姓名和否定词不作为确定结论。双方原话、用户事后解释与智能体假设分开。

只补会改变判断的缺口：这次想得到什么、是否已付费/有旧约、交付和报价事实、谁有审批权、对方是否要求停止联系。有信息就用，不重复盘问。不完整材料也可以先给局部诊断，明确缺失及不确定性。

## 1. 甲方意图分析

每项按照以下格式写，不能只给“预算不足”“想白嫖”“在压价”的标签：

|字段|要求|
|---|---|
|意图假设|当前想完成的任务，如明确总价、比较范围、核风险、向内部汇报、减少投入、结束交流|
|依据|U编号＋精确原句或具体动作；知道什么，不知道什么|
|性质|对方明说的诉求 / 行为事实 / 分析者假设|
|置信度|高：对方明说；中：多个线索但尚未确认；低：单线索或残缺语境。不是精确概率|
|替代解释|至少一个不同解释；明确说过的事实不制造假矛盾，但其背后动机仍可能有不同解释|
|反向证据|哪些原话不支持这个判断；无则写未见，不能当无反例|
|验证问题|一个低负担问题，或已有明说无需再问；明确拒绝时不为验证动机继续骚扰|
|回应含义|该判断改变哪一步：先报价、核权限、解释范围、补材料、暂停，还是处理已有责任|

避免误判：问价≠预算低；考虑≠借口；不回≠不尊重；索取资料≠同行；拒绝≠需要更强刺激；一位甲方同意≠公司批准。用M01/M03/M08/M29/M31核对现场与关系。没有客户原话时，不能给高置信动机结论。

## 2. 风险点分析

优先按影响与紧迫性排序，列“已发生 / 可能 / 待核”。风险严重度与发生概率分开，缺数据时概率未知，不编百分比。

检查：需求/产品不匹配；预算和付款条件；采购与审批权限；范围/价格/时间不清；夸大效果与收益保证；已经作出的承诺；已购权益/退款/交付缺口；持续联系和信任损害；相关材料的授权与隐私；转介绍/分佣/第三方责任。只报告本案有线索或确需核实的风险，别机械罗列全部。

每项必须有风险R编号、对话U依据、相关M/E依据、触发条件、影响、严重度、目前状态、处置动作与责任人/待确认项。优先解决已有责任，再讨论新成交。内容涉及专业判断时明确需要的专业证据，不能把销售话术当法律、医疗或财务结论。

## 3. 逐段话术诊断

先判断对话在哪个环节卡住，再检查具体表达。每条D诊断至少包含：

1. **原句与位置**：谁说、U编号、精确摘录；语序不能被重写成“原话”。
2. **当前问题**：没回答问价、过早推产品、提问无目的、暗含保证、贬低客户、信息碎片化、角色错位、跳过旧权益、越过拒绝等；只指可观察行为。
3. **可能影响**：增加理解成本、放大疑虑、损伤信任或形成承诺风险；“可能”不是已发生的丢单原因。
4. **原因假设**：比如误把价格问题当购买意愿不足；与原句事实分开，避免给销售贴人格标签。
5. **纠正方法**：先删哪类内容、补什么事实、改变什么顺序、何时停止；引用相应M/E。
6. **替代说法**：可发送版或待填版；明确“分析者新拟”，不编价格、排期和案例。
7. **为什么这样改**：对应甲方意图与风险R编号，并说明尚不能解决的问题。
8. **检验**：看对方是否理解范围、是否补充关键信息或是否按偏好收尾；不能把立即付款当唯一正确反馈。

不为凑报告逐句挑错。有效句要说明可保留的功能。诊断不能用“后来成交/失败”倒推每句话都对/都错。

## 4. 回应话术分析

默认只给当前最需要的一版简短草稿；未要求解释时不自动展开逐句分析。确有两种可行路线时给A/B，如“信息足够直接说明”与“关键事实未知先核实”；不同版本必须在行动、前提或承诺上有区别，不只是换几个礼貌词。

用户要求逐句分析或完整报告时，逐句说明：这句话解决哪个意图I、缓解哪个风险R、承担什么功能（承接/答题/说明限制/给选择/收尾），用了哪些M/E/T；用词、称呼、句长节奏和情绪强度为什么适合这个关系。对话稿不能含模型内部分析、知识库编号或不自然的流程术语。

原句、基于原文改写、分析者新拟三类分别标明。存在未填事实槽位就写“待填，不可直接发送”。已知事实充分时不要用空槽位逃避实际回答。对方拒绝推荐但仍索取费用说明时，只提供其要求的信息，不借答题重启营销。

## 5. 完整报告的固定结构

1. **结论摘要**：当前卡点、最先处理的一件事、结论范围。
2. **事实与缺口**：角色、阶段、目标、时间线及不完整处。
3. **甲方意图表**：I编号、依据、替代解释、置信度、验证方式。
4. **风险清单**：R编号、证据、影响、优先级、处置。
5. **谈单话术诊断**：D编号、原句、问题、纠正步骤、替代说法。
6. **候选回应与逐句分析**：A/B、适用条件、每句功能、来源与停止条件。
7. **下一步与复盘**：立即动作、暂不做的动作（仅实际相关时）、观察结果、还需核实的信息；是否适合形成用户案例候选。

短问短答不强制输出七大段，但内部仍遵循同样边界。用户要求报告时生成Markdown；本地工具`diagnosis_report.py`只检查结构、原句和引用编号并排版，语义判断由Skill完成。工具通过不代表意图推断正确。

## 6. 接到真实反馈后

把“建议回复”“实际发送”“甲方反应”“支付/退款/交付”按时间分开。成功案例仅说明这次实际发生什么，检查同时变化的价格、渠道、产品、关系和时机。用[案例学习规程](case-learning.md)更新用户局部经验；不能据一次成交宣称资料作者方法获因果验证。

## 销售策略诊断补充（2.2.0）

涉及谈单时按[销售策略规程](sales-strategy.md)先检查阶段错配、意图证据、预算与价值混淆、采购决策链、未核损失、越权让步及下一步缺失。报告中写原句/上下文→问题证据→风险→纠正步骤→新回复→下一步与观察点；这些内容融入现有七部分，不改变diagnosis_report.py的输入合同。无依据时写可能风险，不把合理回答硬判为错误。
