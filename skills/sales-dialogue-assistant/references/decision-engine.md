# 方法论决策引擎：从问题到候选方案

版本2.0.0。设计来源：用户本轮要求；方法事实来源：[43方法卡](method-cards.md)及[来源上下文](method-sources.md)。路由、优先级与评分是分析者设计，不是作者原话或科学效果公式。

## 输入与输出

输入必须区分“客户原话”“已核事实”“销售解释”。需要：具体问题、希望达到的结果、关系与阶段、已有权益/合同、产品能力、价格范围、联系偏好、已知信息和未知项。不是每次都问全套；仅当缺失会改变建议时追问。结构化事实比关键词重要。事实有冲突时先保留冲突，不默默择一。

输出顺序：问题分类与依据 → 必须遵守的条件 → 缺失信息 → 方案A/B → 差异与冲突裁决 → 验证/退出条件 → 来源。只需一句回复时，在内部完成筛选后输出简短草稿，不把整个方法库塞给客户。

每个方案都包含：目标、适用条件、选用的M编号、动作顺序、对应E编号、成本、风险/取舍、停止条件和结果检查。类型匹配只是方法检索，不计算成交概率。方法可以跨三个维度组合：例如报价问题用M17答价、M35澄清范围、M18限定承诺，再用M26设计复盘。

## 问题类型与分流

|类型|方案A通常处理|方案B通常处理|关键辨别|
|---|---|---|---|
|求助初接触|来意、背景、单一请求|自行试做后带阻塞请教|是请求帮助还是让对方代劳|
|情绪回应|倾听和承接|对方愿意时拆解实际问题|只想被听见还是希望建议|
|免费索取|核权益后讲清范围|真实新服务或结束新增请求|是否已付、是否本来应该做|
|合作洽谈|权责明确后合作|限定范围的小试点|贡献、权限和旧约|
|需求澄清|先答当前问题再补缺口|先核适配再推荐|问能否/怎么做/多少钱|
|报价嫌贵|真实报价及范围|真实减项或暂停|是否明确问价、有无可选供给|
|犹豫拖延|具体顾虑的事实回答|保留空间、暂停|不想买、暂不买、不适合|
|效果保证|可核交付与不确定性|无法匹配就不接|原约责任和新承诺|
|投诉冲突|事实与补救|书面核实/授权升级|产品问题不能被情绪化解释替代|
|催进度|依赖与真实排期|先完成最小可验收部分|谁欠什么、前置输入是否齐全|
|结束合作|按约收尾结算|必要交接与争议处理|退出不取消旧责任|
|复购转介绍|回顾交付与下一阶段|自愿介绍的低负担入口|不把感谢变成购买义务|
|内容引流|人群—内容—产品相连|复用小样并核成本|流量与净收益分开|
|经营决策|按目标及完整成本选择|试点检验再扩大|成功/失败都保留|

## 组合算法

1. **识别任务而非人格**。允许多类型同时存在，例如“嫌贵且要求保证”同时调用价格与结果边界。保留来源；不把客户归为固定难缠人格。
2. **先检查不能违反的条件**。已购义务、明确拒绝、真实能力、可支配预算、不得编造事实是应用约束。优先级来自助理规格，不是宣称作者所有时期都如此。
3. **检索与过滤**。用问题类型和关系阶段召回M卡；逐条看前置条件。条件已知不满足则排除购买路径；未知则列条件候选和必要问题，不能视为满足。词汇命中数只用于排序。
4. **按功能组合**。诊断（M01/M08等）→回应（M06/M17/M30等）→推进或退出（M10/M24等）→验证（M26/M40等）。一个方法没有覆盖的功能由另一个补足；不为了“组合”重复相同动作。
5. **裁决冲突**。查[10项矩阵](conflict-policy.md)，必要时再查历史矛盾附录。事实/责任与同意约束优先于成交优化；当前需求优先于套流程；存在真正冲突时并列双方原话。无法裁决则提出可观察的小验证或停止新增承诺。
6. **形成不同路径**。A回应当前任务，B降低范围或先验证。差异必须落在范围、顺序、资源或可逆性，不能只是把语气变柔和。无第二可行路径就明确只有一个；硬约束不允许作为候选取舍。
7. **生成回复**。按[模板](templates.md)和[风格](style.md)做语境适配。生成句标“依据方法新拟”；只有文本、角色、关系和事实均相符的原句才标原句。未填槽位不可直接发送。
8. **终检**。当前问题是否回答、旧权益是否遗漏、是否偷偷增加期限/费用/保证、是否尊重停止联系、方案的验证动作能否真实观察。未达到则退回相应步骤。

## 本地参考实现

执行`python scripts/decision_engine.py --input /绝对路径/问题.json`，结果输出到终端；可加`--output /绝对路径/新结果.json`。输出不得覆盖已有文件、输入、Skill自身或L1。程序只用Python标准库，不访问网络，不调用模型，不外发原文。

```json
{
  "problem": "客户明确问现有服务多少钱，又担心买后没有效果。",
  "goal": "答清价格与范围，保留购买选择",
  "types": ["报价嫌贵", "效果保证"],
  "relationship": "售前初次咨询",
  "stage": "了解价格",
  "known_facts": ["现有服务价格及范围已由业务方确认；具体值由实际记录提供"],
  "unknowns": ["客户的具体目标是否在该范围内"],
  "constraints": ["不新增优惠，不许诺收益"],
  "facts": {
    "direct_price_request": true,
    "price_known": true,
    "scope_known": true,
    "paid_obligation": false,
    "delivery_capability": "confirmed",
    "budget_fit": "unknown",
    "contact_preference": "allowed"
  }
}
```

`true`表示调用者已核实，不能让程序仅凭这几个标志生成具体价格或效果。自由文本中的事实仍需人工/模型理解；当前程序不会自动从“不要再联系”推断所有同意边界，调用者必须把确认后的语义映射到`facts`。

### 字段与未知值

`problem`必填非空文字；`goal/relationship/stage`为文字；`types`为表中类型数组；`known_facts/unknowns/constraints`为字符串数组。`facts`只接受定义的键，拼写错或类型错直接报错，不静默丢弃。

- 布尔或null：`paid_obligation`、`complaint_open`、`refund_requested`、`direct_price_request`、`price_known`、`scope_known`、`existing_terms_known`、`has_new_value`、`can_change_scope`、`decision_authority`、`wants_listening_only`、`borrowing_to_buy`。
- `contact_preference`：`allowed / stop_marketing / customer_will_contact / unknown`。
- `delivery_capability`、`budget_fit`：`confirmed / insufficient / unknown`。
- 未提供的事实保持未知。未知是否已购不能视为未购，未知是否能交付不能视为能交付。

返回状态：`insufficient_context`没有可用分类；`conditional`缺关键事实或分类仅关键词候选；`ready_for_review`可供审阅但非自动发送许可；`closed_for_marketing`停止营销；`no_current_sales_plan`当前能力/资金条件不允许推进购买。原有责任即使销售暂停仍要处理。

## 一组具体候选（分析者模拟，非作者原句）

情境：企业客户明确问已确认范围的报价，同时要求保证三个月回本。尚未付费；服务商能交付既定培训，但无回本证据。具体金额和日期均由业务方提供，这里不补造。

**A｜如实答价，再说明承诺边界**。条件：价格范围明确、确能交付、对方愿意继续了解。先用M17回答价格及包含项；用M35确认双方理解一致；用M18说明能保证的交付、不能承诺的回本和已有退费安排；邀请对方核对目标是否匹配。优势是及时回应，成本是一轮精准说明；风险是对方仍只接受保证。验证：客户是否准确理解范围及结果不确定性。若只接受回本保证则停止该交易。出处：M17/M35/M18中的E30—32、E106、E34—36；问价反例C28。

**B｜不接不匹配的保证要求，另核是否存在真实较小范围**。条件：对方明确以保证为购买前提，或当前供给无法支撑其目标。M04/M36先说明不适配；若双方自愿且确有小范围服务，可按M40明确投入上限与验收再讨论；没有该产品就不创造“低价体验套餐”。优势是减少错误承诺，代价是可能失去此单；不能宣称更能成交。验证：是否守住旧约、新约和能力边界。出处：M04/M36/M40中的E07、E114—116、E189—190；能力反例C32。

选择差异：A解决信息不足，B解决目标与供给不匹配。硬约束如不作虚假保证不能为提高成交率而被权衡掉。没有匹配供给时，“不成交”也是合格决策结果。

## 可用范围与缺口

这是确定性参考引擎加语义调用规程。当前确定性路由覆盖31/43方法；其余M03、M07、M14、M16、M20、M25、M28、M29、M31、M32、M34由Skill根据语义检索组合，M43仅作为压力模型研究与冲突提醒，不直接生成施压动作。全部43卡都是正式知识规格，不表示程序自动选择了全部43卡。

已知限制包括：关键词无法可靠处理复杂否定、隐喻和多轮对话；业务权限/实际条款不会自动查证；历史688张力未全部编码；没有真实业务最优策略或成功概率模型。出现这些情况，Skill须回到方法卡与上下文，明确人工判断，不假装程序已经解决。每候选至多组合4个方法，其他召回项列为deferred_methods，先解决权益和当前明确问题。
