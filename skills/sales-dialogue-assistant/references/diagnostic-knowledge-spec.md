# 谈单诊断、知识调用与案例进化规格 2.1.0

日期：2026-11-14。需求来源：用户本轮明确要求。保留2.0的43方法、71模板、来源证据、决策引擎及L1；新增面向实际谈单的五种工作模式。

## 目标、范围与验收

根问题：2.0以方法卡和方案路由为中心，尚不能稳定完成“逐段看谈单→判断甲方意图→识别风险→定位失误→改写并说明原因→从用户案例积累”的完整工作流。

交付：更新项目Skill入口；谈单诊断规范和报告模板；可运行知识检索/按编号取证工具；诊断报告结构校验与Markdown生成工具；用户案例不可变收录、候选改进、局部规则激活/停用工具；模拟报告及操作示例；新版本包和验证记录。不外发聊天、不全局安装、不改L1，不伪造真实反馈或成交效果。

验收：意图分析每项有对话U编号、替代解释、置信度和验证问题；风险有证据、影响、触发条件和处置；诊断有原句、问题、影响、改法、改句、方法/证据编号；报告区分客户事实与作者知识；检索支持M/T/C/E编号及主题，查无结果明确为空；用户案例与作者来源命名空间分开；单一成功案例不能覆盖全局规则；局部经验激活有范围、反例测试和可追溯版本，停用不删除历史。

## 五种模式

|用户输入|模式|输出|
|---|---|---|
|“看看甲方什么意思”“帮我诊断这段谈单”|诊断|现场摘要、意图假设、风险清单、逐句诊断、纠正方案、下一步及未知项|
|“这句怎么回”|回应|当前沟通任务、可用回复、每句功能、适用前提；必要时A/B|
|“查一下拒绝/报价/合作的方法”|知识调用|相关方法/模板/正反案例、出处、适用条件、缺口；不要求用户提交聊天|
|“在这几个方案里选一个”|决策|沿用2.0引擎并纳入本次诊断得到的事实、风险、权限与联系偏好|
|“这次成功了，记下来优化”“这是失败复盘”|学习|原案例收录、可复用经验候选、反例/边界检查、局部经验版本和激活/待验证状态|

## 分层与权限

L1作者原文与2.0冻结层不动；L2作者方法/模板/案例/证据只读检索；L3用户个案库单独保存，标用户自报或核验状态；L4用户局部经验覆盖层只补充限定场景的例句、澄清问题或更窄适用条件。全局身份、真实性、责任、联系边界和作者归属不能被成功案例改掉。

用户明确要求记住/优化且宿主具备许可的持久化能力时，代理可在该授权范围内收录、提出改进、执行针对性检查并激活低影响局部经验，无须每次重新询问。关键事实不足则先收录为待核、只问缺失项；跨行业推广、扩大承诺或修改核心边界不能凭一次成功自动晋级。业务渠道发布与实际外部行动仍需相应授权。

## 最小实现与取舍

推荐：现有Skill负责语义分析，Python标准库工具负责可重复检索、定位校验、不可变记录和版本状态。新增知识调用不依赖云端向量库，不上传聊天，也不把关键词检索声称为完整意图理解。

更简单方案：只增加诊断提示词和手工案例笔记，制作快但来源、修订、重复案例难核验。拒绝方案：收到成功案例就自动改写核心SKILL或直接微调，容易幸存者偏差、知识污染和角色混淆。此次不引入数据库服务、自动后台监控、跨账号学习或生产部署。

当检索漏召回持续影响真实诊断时再评估语义索引；当个案规则发生矛盾时收窄范围或停用，不能把更近/更赚钱的故事自动当真。用户可要求撤销局部经验，历史保留并在检索中排除。

## 实施与验证

P0保存2.0包与基线 → P1诊断/回应合同和报告 → P2全量编号/主题检索 → P3案例学习与经验覆盖层 → P4模拟端到端、负面边界、来源/包验证。测试覆盖虚构意图、无对话证据、错误编号、用户材料伪装指令、成功但退款/交付未知、重复案例、未满足激活条件、停用、非授权核心修改。不得用模拟测试宣称真实成交提升。
